# SltBox 2026102701

本版重做种树动物图鉴，调整采摘和收藏反馈，并修复两条可能导致树能量回落的同步路径。同时汇总自 2026102402 之后已提交的树木卡包、装饰和设置界面改进。

## 动物图鉴：184 种动物与新的生态条件

- 图鉴固定为 **飞鸟 60 种、小动物 44 种、蝴蝶 80 种，共 184 种**，分类顺序统一为“飞鸟 / 小动物 / 蝴蝶”。
- 使用成对的透明 PNG：已发现的亮图与未发现的灰图各 184 张，原图直接导入，替换旧 SVG 图鉴资源。
- 物种身份按实际图片整理，`albatross`、`peacock` 等本次素材中的蝴蝶按蝴蝶分类。
- 遇见条件包含季节、时段、适宜天气和偏好天气。季节使用北半球的立春分季逻辑，适用的热带物种可以全年出现。
- 蝴蝶按各自季节，在清晨或白天、晴到多云的适宜天气出现。当前环境没有合理物种时，允许本次没有动物，稍后再检查。
- 动物按习性分配到树上、草地或天空；动作锚点和轨迹跟随位置类型以及树木阶段 1–5。保持现有放大尺寸、点击范围和画布边界。
- 背包的出现条件增加“地点：树上 / 草地 / 天空”，便于理解动物出现的位置。

## 点击反馈：先播放动画，再提交请求

- **采摘果实**：点击后先播放约 430 毫秒的放大、发光和淡出动画，再执行树状态同步及采摘请求；接口确认成功后，显示实际到账数量。
- **获取动物**：点击后先播放约 320 毫秒的收缩淡出动画，再提交收藏请求，随后刷新背包和状态。
- 请求期间防止重复点击。失败时恢复对应对象和可点击状态，保留失败反馈；登录失效异常也进入采摘错误处理。
- 隐藏或卸载种树界面会取消尚未完成的采集动画，阻止这次动画继续触发请求。已经发出的请求仍按原有服务逻辑处理。
- 关闭系统动画时保留静态反馈，避免强制播放移动、缩放动画。

## 树能量同步：保护跨天与重试期间的增长

- 修复跨 UTC 日后“今日增长”归零，被误判为本地落后、进而覆盖尚未上传总能量的问题。不同日期的当天增长不再直接比较。
- 修复“服务端已入账但响应丢失，随后继续输入并重试”时漏记新增能量的问题。待上传队列现在保存完整请求、提交时的本地快照和确认基线，同一操作号始终重传同一份请求。
- 原请求只确认它实际提交的增长；期间新增的能量继续保留，下一轮使用新的操作号上传，避免正常的服务端去重把新增部分一起当成已确认。
- 跨天重试时保留提交快照的日期，避免从今天的增长中扣减昨天的数值。
- 旧版待上传队列缺少原始请求内容，继续处理前先保存本地快照，供核对和补救使用。
- “设置 → 功能格子 → 种树”提供手动同步校准入口；自动同步周期仍为五分钟。

### 已丢失的数据如何补救

升级可以防止上述代码路径再次丢失增长，**不会凭空补回已经被覆盖的历史按键数**。若本地完整数据仍在，先保留备份再同步；若数值已经回落，需要使用 `progress.json.bak`、冲突快照、账户云备份以及服务器操作记录，核对尚未入账的净差额。不要把多个重叠备份直接相加，也不要先删除同步状态。

详细步骤见仓库文档 [树能量同步与数据补救](https://github.com/sltalex/SltBox/blob/v2026102701/docs/tree-energy-sync-recovery.md)。

## 树木卡包、装饰和界面整理

- 将树木装饰卡包整合到商城购买、背包使用的流程，提供单次和十次卡包选项，价格由服务端配置。
- 树木装饰的编辑入口集中到种树设置，支持同种装饰使用多个实例，并按拥有数量管理可放置数量。
- 整理商城、背包、果实市场与种树设置的布局，改善装饰预览、操作区域和统计控制的呈现。
- 补齐两处树木装饰控件的 WinRT `partial` 声明，使发布构建能够生成相应的 AOT 互操作代码。
- 这些内容来自本次发布基线中已经提交的功能；其他任务尚未提交的本地界面改动不包含在安装包中。

## 图鉴升级与旧客户端兼容

- 新客户端使用 v2 图鉴协议。旧客户端继续使用只含共同物种的兼容目录，不会收到无法识别的新物种 ID。
- 图鉴版本写入本地缓存。旧图鉴缓存、旧云备份和旧客户端恢复请求，不会把重置前的动物库存或发现记录重新写入 v2。
- **服务端已于 2026-10-26 完成一次动物收集历史重置**，覆盖遇见状态、库存数量、发现记录和捕获幂等记录。原数据备份表保留供运维回滚。本次安装包发布不会再次执行重置。
- 该重置针对动物收集数据；它不等同于树能量补偿或树能量清零。新图鉴需要从重置后的收集进度重新开始。
