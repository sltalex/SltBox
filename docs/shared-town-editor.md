# 共享小镇素材与编辑

当前入口为 Debug 版“设置 → 种树 → 小镇预览”，由现有服务端灰度名单控制。此窗口使用全局 `main` 地图，个人种树、果实和真实装饰库存规则不变。

## 素材加载

认证下载由 `SharedTownSession` 完成。PNG 必须符合已发布目录中的尺寸和 SHA-256，校验后通过临时文件原子替换到本机 `town-prototype/sheets` 缓存。页面从独立本地虚拟主机读取文件，允许画布裁剪，不能直接访问远端网站。卡片、预览和地图纹理来自同一次图片解码。

目录和图集请求合并；普通刷新保留已解码图集。下载最长 20 秒，失败提供“重试素材”；目录请求失败也有独立提示。账号和发布版本变化时拒绝过期结果。慢网络下不会叠加尚未完成的轮询请求。

## 编辑和观察

- 漫游模式：方向键或 WASD 控制人物，镜头跟随，滚轮使用 1～4 倍整数缩放。
- 编辑模式：方向键或 WASD 移动镜头，人物保持原地；右键拖动空白区域也可平移。输入框获得焦点时不移动镜头。
- 右击自己的物件显示“移动”“删除”。选择移动后左击确认，Esc 取消。缺图旧物件仍按服务端占地显示轮廓、选中和删除。他人物件不能修改。
- 返回漫游会取消尚未确认的移动并立即回到人物。
- 右上角小地图显示全部固定地形、人物、视野范围及已加载对象；编辑模式点击可定位镜头，不移动人物。

地形版本为 5。地图宽、高从 384 格各扩至 768 格（32×32 个区块），继续向东和向南扩展，已有地形、物件和人物坐标保留。共享地图不生成中央主树或出生保护区，广场可以建造；河流、河岸和森林继续限制建造。编辑网格和放置预览的绘制层级随地图高度计算，保持在南侧物件上方。

人物位置按世界和账号保存在 `town_player_positions`，与 30 秒后过期的在线名单分开。首次进入由服务端随机选择可站立的地点；以后恢复上次像素坐标。移动期间最多每秒提交一次，停止移动和正常关闭窗口时提交最终位置，关闭会等待保存成功。位置请求串行提交，账号切换后拒绝旧会话请求。若上次位置已被新物件占用，则就近寻找可站立的地点并保存修正结果。重复刷新世界不会把正在移动的人物重新传送回出生点。旧个人原型的示例布局不作为共享地图启动条件。

升级已有数据库使用 `database/026_shared_town_player_positions.sql`：创建持久位置表、导入旧在线名单中尚存的位置，并扩大世界尺寸。重复执行不覆盖已有位置或重复增加世界版本；原有物件、素材发布和灰度名单保留。

随后执行 `database/027_shared_town_map_768.sql`，将地图扩至 768×768、地形版本升至 5，并增加一次世界版本。重复执行不再增加版本，也不会缩小之后的地图；不修改人物位置或物件记录。

## 后台占地计算与数据重算

在 `/api/admin?panel=town_assets` 框选、修改显示尺寸或动画帧后，自动计算非透明轮廓底部三分之一的脚底区域。动画取所有帧的并集，按显示像素除以 16 向上取整，并生成碰撞元数据。管理员可以手动修改或重新计算；空区域、无法解码和超过 16×16 格会明确报错。

“预演全部占地重算与就近调整”只读取数据，给出前后清单和预演哈希。应用时锁定世界及素材数据，重新检查哈希。合法原位置保留；冲突对象按距离及固定坐标顺序就近调整。不能安置任何一个物件时整批失败。

已发布、草稿以及已放置但从当前目录移除的历史 Stardew 物件均参与重算。历史配置仍保留；新发布配置只更新原来已发布的素材，不把其他草稿发布出去。SVG 装饰目录和真实库存不参与重算。

本次线上应用前备份了服务端文件、服务配置及小镇相关表。原有 18 个物件保留，其中 17 个 Stardew 物件参与计算，8 个调整了位置；发布目录中的两项素材占地为 8×2、4×3。灰度名单仍为原有两个账号。
